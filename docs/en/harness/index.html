ENDE

Harness

What your agents know, what they work with and what they may do — the same for Claude Code, Codex, Gemini CLI, Kimi and Hermes.

Every coding CLI ships its own "harness": its own instructions file, its own tools, its own approvals. Run five of them on one project and you get five rulebooks. OpenCognit puts one harness on top — the same rules, the same checks and the same knowledge for every agent.

The Harness shield in the left bar opens the overview. Above the quota a line shows whether there is something to do in the active project (● with the number of notes).

Two layers

  • Project layer: AGENTS.md in the project folder. Codex, Kimi and Hermes read it directly, Claude through a single @AGENTS.md line in CLAUDE.md, Gemini automatically in OpenCognit sessions. It belongs to the project and also works without OpenCognit (colleagues, CI).
  • OpenCognit layer (OPENCOGNIT.md): generated for every session at startup and never written into the project. It contains the session name, folder and branch, how the agent reports back, what the guardrails block, the test command and your custom instructions (Settings → Custom instructions). The ⓘ in every session header shows exactly what that agent got.

Agents can ask at any time who else is working on what:

The page

  • Overview — status light, four cards (instructions, OpenCognit layer, tools, rules) and a list of notes, each with a matching action.
  • Instructions — what each CLI reads and whether it is consistent; findings for AGENTS.md; on the right the OpenCognit layer per CLI.
  • Tools — the MCP servers of all CLIs and the installed skills per CLI.
  • Rules — guardrails, checking agent commands, package guard, secret scan, test gate and "local models only" at a glance, with a jump to edit them.

What is checked

  • AGENTS.md is missing
  • CLAUDE.md, GEMINI.md, .kimi-code/AGENTS.md or .hermes.md contain their own rules the other agents don't see
  • CLAUDE.md doesn't point to AGENTS.md
  • AGENTS.md is very large (from ~12,000 characters it costs noticeable tokens in every session)
  • stale references: mentioned files or folders that no longer exist and npm run … commands missing from package.json
  • MCP servers set up for only some of the CLIs

Merging

Merge … first shows per file what will happen: the own rules move into AGENTS.md as a section, CLAUDE.md and GEMINI.md then only point to it (@AGENTS.md), the files of Kimi and Hermes go away — both read AGENTS.md anyway. Nothing is written until you confirm; afterwards you see the change as a normal git diff.

Free and Pro

The page, all findings and the OpenCognit layer for every session are free. Merging, creating AGENTS.md, copying MCP servers and the per-CLI preview of the layer are part of Pro.
