ENDE

Graph

Four views of your project — knowledge, planning, tasks live and result. Each answers one question.

The Graph shows your project and what the agents do in it. At the top you pick one of four views. Each answers one question and lets you act right away:

ViewQuestionWhat you do there
NeuronsWhat do my agents know about the project?Fill gaps, record decisions
AtlasWho owns what, where does it get risky?Plan tasks for an area
TasksWhat is happening right now, where do I need to look?Answer, approve, rewind
LayersWhat is done — and can I trust it?Adopt, follow up, get a review

All views share the same areas (the largest folders of the project) in the same colors. Rings, Links and Timeline have been folded into these four as of 0.7.0. The control room in Neurons gives the overview of all four.

Neurons

The start view shows your project as a neural web, arranged like a brain map:

  • Related areas (imports, shared changes) sit next to each other, each in its own color.
  • One trunk per subfolder, every tip a file; large folders are spread over several trunks, and subfolder names appear as you fly closer.
  • Connections only exist where there are real relations.
  • When an agent works, impulses run along the branches and the core fires. Its name tag shows what it is on; a click opens its chat.
  • Scroll zooms toward the mouse, drag looks around, a click on a neuron flies there, Esc returns to the overview. Zoom out and you see the universe: every other workspace as its own neuron around it — where agents work there, their branches flash.
  • Two agents in the same area or on the same file are reported as a conflict.
  • A short live ticker lists the latest accesses (“Claude Code #2 edits Hero.tsx”).

Control room

Space shows just the web, the control room puts panels around it — the overview of everything:

  • Needs you at the top: approvals (straight Allow once or Deny), questions, stuck CLIs, limits.
  • On the left folders with real line counts and the agents with activity, file and task status ("task t-4f2a · working / running tests / done / needs you").
  • On the right the overview of the four views — a click jumps there: Tasks (how many work, stalls), Result (how much is verified, what is red), Planning (overlaps, areas without tests) and Knowledge (gaps).
  • Below: figures, hot spot, quota forecast, log, raster and heat map.

Knowledge

In Space, the Knowledge button at the top right opens a panel on the left with everything each agent learns about your project:

  • Instructions — AGENTS.md, CLAUDE.md and friends; a click opens them in the editor.
  • Decisions — what the orchestrator or you recorded ("prices always in cents"). Add new ones right here; they go into AGENTS.md, which every agent reads.
  • Gaps — areas where agents worked in the last 7 days that no instruction or README describes. That is where agents guess; "Describe" starts a line for you to fill in.
  • Skills and memory of the configured CLIs.

The view slows down when it is not visible and simplifies distant neurons, so it stays smooth even with many agents.

Atlas — plan

The Atlas shows the project as a brain map across the whole surface: every area is a lobe of cells, as large as its file count.

  • Where agents work, the lobe glows; every agent stands next to it with a name tag.
  • Two agents in the same area get a red ring — risk of conflict.
  • Areas whose code has no tests get a dotted outline. (Tests in their own folder such as tests/ count for the files they match.)
  • Click an area to open Plan on the right: who owns it (file scopes of open tasks), whether tasks overlap and whether tests exist. Below, write a new task for this area — it goes to the orchestrator, which assigns it with exactly that file scope. Overlaps get solved before the work starts instead of being merged afterwards.
  • A click on an agent opens its chat, Esc shows everything again.

Tasks — live

The Tasks view shows what every agent is doing right now, step by step, and in which folders:

  • Every agent has a tile: what it is doing, its last steps and a border that fills up as the task progresses (estimated from its steps; done = closed and briefly bright).
  • The areas are on the left, threads in between: reads flow to the tile, edits flow back into the folder, each with a small label (READ, EDIT). Fresh threads glow in the agent's color and cool down to an ember over about 25 seconds — you see where work happened a moment ago.
  • Stalls ("last step 6 min ago"), questions and approvals stand out on the tile.
  • Needs you below the tiles: allow or deny guardrail holds, answer questions with Yes/No or your own words — without switching to the terminal.
  • Rewind: drag the timeline at the bottom (or press play) and the view shows any moment of the session, with markers for start, questions, approvals, test results and done. "Live" returns.
  • A click on a tile opens the agent's chat.

Everything comes from your machine: sessions, event log, audit log and file accesses of the last 24 hours. The view only draws while something moves.

Visible right away are threads, the orchestrator and Claude Code, Codex and Gemini in the terminal (via their check hook, see Guardrails). Other CLIs in the terminal appear once their log is readable.

Layers — result

Layers builds the project like a neural network: agents on the left, areas in the middle, the result on the right. Impulses run from left to right while work goes on.

As soon as an agent has delivered something, the Result column appears on the right — per agent:

  • Report — what the agent reported, or "round done · 3 files"
  • Tests — green, red or running (including the app's mandatory check)
  • Review — a second opinion from an agent of another vendor: "Review by …" starts e.g. Codex for what Claude built, in the same folder. The reviewer cannot change files and reports "looks good" or a list of findings.
  • Adopt, Follow up (when red or with findings) and Diff

A row only turns gold when the report is in, tests are not red and the review has no findings — what an agent merely claims does not count.

The graph views draw at 30 frames per second, 8 in the background.

Chat beside the graph

You don't have to leave the graph to tell an agent something. Click an agent and its real terminal (or thread) opens on the right; the speech-bubble button at the top right shows and hides the chat.

  • Tabs at the top for the orchestrator and every session of the workspace — click through them without switching views.
  • Type or dictate (Ctrl+Space) as usual; next to it, the graph shows live which files the agent touches.
  • Drag the left edge of the chat to resize it; the width is remembered.

Harness

What your agents know, what they work with and what they may do — the same for Claude Code, Codex, Gemini CLI, Kimi and Hermes.

Editor, search & Git

Edit files — next to the terminals or on their own, with before/after —, search the project, review changes and commit.
