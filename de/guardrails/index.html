Riskante Befehle
warten auf dein OK.

Agenten führen Befehle selbst aus. OpenCognit prüft jeden davon, bevor er läuft — ein git reset --hard wird abgelehnt, ein git push wartet auf dich, und nichts wird stillschweigend durchgewunken.

So sieht es aus

Ein Push, der wartet,
bis du ihn erlaubst.

Was du bekommst

Schutz für das, was Agenten
selbst ausführen.

I

Drei Stufen

Blocken lehnt den Befehl ab, Freigabe hält ihn an, bis du entscheidest, Warnen lässt ihn laufen und gibt Bescheid. Regeln sind reguläre Ausdrücke, die du ändern und ergänzen kannst.

II

Eingebaute Regeln

Geblockt: git reset --hard, git clean -fdx, rm -rf auf / oder ~, DROP TABLE, mkfs. Zur Freigabe: git push, npm publish, Deployments, Migrationen, curl … | sh.

III

Für alle fünf CLIs

Claude Code, Codex, Gemini, Kimi und Hermes starten mit einem kleinen Prüf-Hook — jeder Shell-Befehl, den ein Agent selbst ausführt, wird vorher angefragt.

IV

Freigabe in der Kachel

Eine Karte mit Einmal erlauben, Für die Session erlauben und Ablehnen erscheint direkt in der Kachel des Agenten — ohne das Raster zu verlassen.

V

Vorher ausgepackt

Befehle werden vor der Prüfung ausgepackt: bash -c, eval, $(…), Verkettungen, Variablen und Verschleierung. Vor git commit wird der Diff nach Schlüsseln und heiklen Dateien durchsucht.

VI

Nie durchgewunken

Ist OpenCognit nicht erreichbar, fragt der Agent dich selbst. Deine eigene CLI-Konfiguration bleibt unberührt — der Hook gilt nur für Sessions, die OpenCognit startet.

So läuft es

Drei Schritte zu sicheren Agenten.

I

OpenCognit installieren

Linux oder Windows. Die eingebauten Regeln sind von Anfang an aktiv.

II

Agenten starten

Jede Session bekommt den Prüf-Hook automatisch.

III

Entscheiden, wenn es zählt

Riskante Befehle warten auf dich; Regeln passt du unter Einstellungen → Guardrails an.

Fragen zu Guardrails

Was, wenn ich einen Push erlauben will?

Klick in der Karte auf Einmal erlauben oder Für die Session erlauben. Ablehnen schickt dem Agenten eine Absage mit Begründung.

Kann ein Agent eine Regel umgehen?

Befehle werden vorher ausgepackt (bash -c, eval, $(…), Variablen), und der Agent bekommt eine Absage mit der Bitte, sie nicht zu umgehen.

Ändert das meine CLI-Einstellungen?

Nein. Der Hook kommt nur in Sessions, die OpenCognit startet; ~/.claude, ~/.codex und ~/.gemini bleiben unberührt.

Kann ich eigene Regeln anlegen?

Ja. Jede Regel ist ein regulärer Ausdruck mit Stufe — eigene legst du unter Einstellungen → Guardrails an.

Was kostet es?

Kostenlos mit bis zu 4 Agenten und 2 Projekten. Pro kaufst du einmal — kein Abo zusätzlich zu deinem Tarif.
